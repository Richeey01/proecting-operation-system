# Практическая работа №9 — Вариант C

## Собственный аллокатор памяти на C

В рамках варианта C реализован собственный аллокатор памяти поверх одного большого региона, выделенного с помощью `mmap`.

Поддерживаются операции:

- `my_malloc()` — выделение памяти;
- `my_free()` — освобождение памяти;
- `my_realloc()` — изменение размера выделенного блока;
- разбиение свободных блоков;
- объединение соседних свободных блоков;
- две стратегии размещения: First Fit и Best Fit.

Размер региона памяти составляет примерно 1 MiB.

## Структура

Файлы:

- `allocator.h` — структуры и объявления функций аллокатора;
- `allocator.c` — реализация аллокатора;
- `allocator_test.c` — базовые тесты `malloc`, `free` и `realloc`;
- `benchmark.c` — сравнение First Fit, Best Fit и системного `malloc`;
- `Makefile` — сборка проекта и запуск Valgrind.

## Структура блока

Каждый участок памяти содержит служебный заголовок `Block`.

Он хранит:

- размер блока;
- признак того, свободен ли блок;
- указатель на следующий блок.

Также используется `max_align_t`, чтобы возвращаемая пользователю память имела корректное выравнивание.

## First Fit

First Fit просматривает список блоков с начала и выбирает первый свободный блок, размер которого достаточен для запроса.

Преимущество:

- обычно работает быстрее, потому что не обязательно просматривать весь список.

Недостаток:

- может быстрее создавать небольшие свободные промежутки в начале памяти.

## Best Fit

Best Fit просматривает свободные блоки и выбирает самый маленький блок, который всё ещё способен удовлетворить запрос.

Преимущество:

- пытается уменьшить количество неиспользованного пространства внутри выбранного свободного блока.

Недостаток:

- поиск обычно медленнее, так как необходимо просматривать больше блоков.

## Разбиение блоков

Если свободный блок значительно больше запрошенного размера, он разбивается на две части:

1. занятый блок нужного размера;
2. новый свободный блок.

Это позволяет эффективнее использовать регион памяти.

## Объединение блоков

После вызова `my_free()` соседние свободные блоки объединяются.

Это уменьшает внешнюю фрагментацию и позволяет позднее выделять более крупные участки памяти.

## Формула внешней фрагментации

Для собственного аллокатора использовалась формула:

`Fext = 1 - largest_free_block / total_free_memory`

где:

- `largest_free_block` — самый большой свободный блок;
- `total_free_memory` — общий объём свободной памяти.

Чем ближе значение к 0, тем меньше внешняя фрагментация.

## Benchmark

Использовались три сценария.

### 1. Small

Выполняется большое количество выделений небольших блоков памяти.

### 2. Alternating

Сначала создаётся множество блоков, после чего освобождается каждый второй блок.

Такой сценарий специально создаёт большое количество отверстий и позволяет проверить внешнюю фрагментацию.

### 3. Large

Выделяется небольшое количество крупных блоков.

## Результаты

| Аллокатор | Сценарий | Время | Peak RSS | Фрагментация |
|---|---|---:|---:|---:|
| First Fit | small | 0.038970 s | 912 KB | 0.0000 |
| First Fit | alternating | 0.040276 s | 912 KB | 0.1262 |
| First Fit | large | 0.000298 s | 1168 KB | 0.0000 |
| Best Fit | small | 0.039470 s | 912 KB | 0.0000 |
| Best Fit | alternating | 0.044428 s | 912 KB | 0.1262 |
| Best Fit | large | 0.000302 s | 1168 KB | 0.0000 |
| glibc malloc | small | 0.000318 s | 784 KB | N/A |
| glibc malloc | alternating | 0.000219 s | 784 KB | N/A |
| glibc malloc | large | 0.000389 s | 1168 KB | N/A |

Для системного `malloc` внешняя фрагментация указана как `N/A`, так как внутренний список свободных блоков glibc напрямую недоступен через стандартный интерфейс.

## Выводы

Системный `malloc` из glibc оказался значительно быстрее собственного учебного аллокатора при большом количестве мелких операций.

First Fit оказался немного быстрее Best Fit, особенно в сценарии с чередованием выделения и освобождения памяти.

Причина заключается в том, что First Fit прекращает поиск сразу после обнаружения первого подходящего блока, тогда как Best Fit продолжает поиск более подходящего блока.

В сценарии `alternating` обе стратегии получили внешнюю фрагментацию `0.1262`.

В сценариях `small` и `large` внешняя фрагментация равна `0.0000`, поскольку свободная память в момент измерения в основном представляла собой один большой непрерывный участок.

Разница между First Fit и Best Fit в данном эксперименте невелика, потому что использованные запросы имеют одинаковые или близкие размеры. На более неоднородной последовательности запросов их поведение может различаться сильнее.

## Проверка Valgrind

Проект был проверен с помощью:

`valgrind --leak-check=full --show-leak-kinds=all --track-origins=yes`

Результат:

`All heap blocks were freed -- no leaks are possible`

`ERROR SUMMARY: 0 errors from 0 contexts`

Таким образом, тестовый запуск не содержит обнаруженных утечек памяти или ошибок доступа.

## Сборка

Сборка выполняется командой:

`make`

Используются параметры компилятора:

`-std=c11 -Wall -Wextra -Wpedantic -Werror`

Проект компилируется без предупреждений.

Для запуска базового теста:

`./allocator_test`

Для запуска benchmark:

`./benchmark`

Для проверки Valgrind:

`make valgrind`

Для очистки:

`make clean`
