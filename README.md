# ПР-2. Bash и системные вызовы (вариант B)

## 1. report.sh
Скрипт принимает каталог, уровень (ERROR или WARN) и необязательный `--top N`, выводит таблицу «модуль → число сообщений» по убыванию числа.
При ошибках аргументов (нет аргументов, неверный уровень, каталог не существует, N не число) справка выводится в stderr, код возврата 1.

Примеры:

    ./report.sh data ERROR --top 3
    db 637 / net 600 / disk 321

    ./report.sh /nope ERROR; echo $?
    (сообщение об ошибке и справка в stderr) 1

## 2. Системные вызовы hello.py
Команда: `strace -f -o trace.txt python3 hello.py data/01.log` (размер файла 19076 байт).

- Всего системных вызовов в trace.txt: **559**.
- К собственно чтению файла data/01.log относятся **8**: openat, fstat, lseek (×2), fstat, read (×2; второй вернул 0 - конец файла), close.
- Остальные 551 - накладные расходы интерпретатора. Перед выполнением одной строки кода Python: запускается (execve), выделяет память (mmap, brk, mprotect), загружает libc и другие библиотеки, настраивает обработку сигналов (rt_sigaction, 66 вызовов), ищет и загружает модули стандартной библиотеки и .pth-файлы (newfstatat - 116, openat, read, lseek, getdents64), читает файлы локали и таймзоны, а также сам файл hello.py.

## 3. Сравнение cat и python3 hello.py

| Программа | Всего системных вызовов |
|---|---|
| cat data/01.log | 119 |
| python3 hello.py data/01.log | 559 |

Вывод: на чтение файла обе программы тратят почти одинаково (около 7-8 вызовов), а разница в накладных расходах. cat - небольшая скомпилированная программа: ей нужны только libc и локаль, поэтому всего ~119 вызовов. Python - интерпретатор, который при каждом запуске инициализируется и загружает модули, поэтому вызовов примерно в 4,7 раза больше. Для простой задачи «прочитать файл» cat эффективнее; удобство высокоуровневого языка оплачивается временем старта и лишними обращениями к ядру.
