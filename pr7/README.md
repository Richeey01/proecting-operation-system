## 1. FIFO — именованные каналы

Сервер принимает арифметическое выражение через FIFO, вычисляет результат и отправляет ответ через отдельный FIFO клиента.

### Запуск

В первом терминале:

```bash
cd ~/pr2-repo/pr7
python3 fifo_server.py
```

Во втором терминале:

```bash
cd ~/pr2-repo/pr7
python3 fifo_client.py
```

Пример запроса:

```text
2 + 3 * 4
```

Результат:

```text
Ответ сервера: 14
```

Сервер обрабатывает запросы последовательно. Для каждого клиента используется отдельный канал ответа.

## 3. Shared Memory и Pipe

Программа `shared_memory_demo.py` передаёт массив из 10 000 000 целых чисел типа `uint64` между процессами двумя способами.

Размер массива составляет 80 000 000 байт, или около 76,29 MiB.

### Запуск

```bash
cd ~/pr2-repo/pr7
python3 shared_memory_demo.py
```

### Результаты измерения

| Показатель | Shared Memory | Pipe |
|---|---:|---:|
| Количество чисел | 10 000 000 | 10 000 000 |
| Размер массива | 76,29 MiB | 76,29 MiB |
| Время передачи и проверки | 0,234 с | 0,232 с |

Результаты получены в одном запуске. Разница в 0,002 секунды слишком мала, чтобы утверждать, что Pipe быстрее в общем случае. Время зависит от нагрузки системы и накладных расходов на копирование, синхронизацию и запуск процессов.

## 4. Сравнительная таблица IPC

| Механизм | Нужна ли синхронизация | Объём данных | Время |
|---|---|---|---|
| FIFO | Для простого обмена запросами и ответами отдельная синхронизация обычно не требуется; нужно соблюдать протокол обмена | Небольшое арифметическое выражение | Не измерялось |
| Unix-сокет | Для простого обмена по соединению отдельные блокировки обычно не нужны; для общих ресурсов синхронизация может понадобиться | Небольшое арифметическое выражение | Не измерялось |
| Shared Memory | Да, если процессы могут одновременно читать и изменять общие данные | 80 000 000 байт | 0,234 с |
| Pipe | Для обычного обмена через `send`/`recv` дополнительная блокировка не нужна; важен правильный порядок сообщений | 80 000 000 байт | 0,232 с |

Время для FIFO и Unix-сокетов не измерялось, поскольку эти программы реализуют калькулятор, а не передачу массива из 10 миллионов чисел. Поэтому напрямую сравнивать их скорость с Shared Memory и Pipe по этим данным нельзя.

## 5. Очистка ресурсов

После завершения программ временные IPC-ресурсы должны удаляться.

- FIFO-сервер удаляет `/tmp/pr7_request.fifo` при остановке через `Ctrl+C`.
- FIFO-клиент удаляет собственный канал ответа после завершения.
- Unix-сервер удаляет `/tmp/pr7_calculator.sock` при остановке через `Ctrl+C`.
- Программа Shared Memory закрывает и удаляет сегмент разделяемой памяти в блоке очистки.

Проверка после остановки серверов:

```bash
ls -l /tmp/pr7_request.fifo /tmp/pr7_calculator.sock
ls /tmp/pr7_response_*
ls /dev/shm
```

Первые две команды могут вывести сообщения об отсутствии файлов — это ожидаемо. В `/dev/shm` не должно остаться сегмента, созданного данной программой. Если там есть другие файлы, не удаляйте их без проверки принадлежности этой работе.

## 6. Контрольные вопросы

### 1. Почему Shared Memory — самый быстрый и самый опасный IPC?

Shared Memory позволяет процессам обращаться к одной области памяти без передачи каждого элемента через отдельный канал. Это снижает расходы на копирование данных.

При этом процессы могут одновременно изменять одни и те же данные. Без синхронизации возможны гонки, чтение неполных данных и повреждение результатов. Программист должен самостоятельно управлять доступом к общей памяти и временем жизни сегмента.

### 2. Что произойдёт, если записать в Pipe, у которого закрыты все читающие концы?

В Unix при записи в канал без читателей генерируется сигнал `SIGPIPE`. По умолчанию он может завершить процесс. Если сигнал игнорируется или обрабатывается, операция записи обычно завершается ошибкой `EPIPE`. В Python это может проявляться как `BrokenPipeError`.
