Результат показывает наличие группы developers.

2. Общий каталог

Был создан каталог:

/srv/shared

Владелец каталога:

root

Группа:

developers

Проверка:

ls -ld /srv/shared

Права каталога:

drwxrwxr-x

Это означает:

root имеет полный доступ;
пользователи группы developers могут читать, создавать и удалять файлы;
остальные пользователи могут читать содержимое каталога и входить в него, но не могут изменять его.
3. Проверка удаления файла

От имени пользователя student2 был создан файл:

/srv/shared/test_student2.txt

Основной пользователь попытался удалить этот файл.

Удаление завершилось ошибкой:

Permission denied

Причина заключается в том, что основной пользователь не входит в группу developers, а для остальных пользователей у каталога нет права записи w.

Важно: для удаления файла нужны права на родительский каталог. Поэтому отсутствие w у пользователя для /srv/shared запрещает удаление файла.

4. Отличие su от sudo

su (switch user) используется для переключения на другого пользователя.

Например:

su - student2

После этого команды выполняются от имени student2.

sudo используется для выполнения отдельной команды с правами другого пользователя, обычно администратора root.

Например:

sudo mkdir /srv/shared

Таким образом, su обычно меняет текущую пользовательскую сессию, а sudo позволяет выполнить отдельную команду с повышенными правами.

5. Почему вход под root по умолчанию заблокирован

В Ubuntu прямой вход под root по умолчанию отключён для повышения безопасности.

Вместо постоянной работы от имени root рекомендуется использовать обычного пользователя и при необходимости выполнять отдельные административные команды через sudo.

Это уменьшает риск случайного изменения или удаления системных файлов.
