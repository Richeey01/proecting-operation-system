# Практическая работа №10 — Страничная организация памяти

## Цель

Реализовать перевод логического адреса в физический, смоделировать TLB с алгоритмом LRU, вычислить эффективное время доступа к памяти и исследовать механизмы виртуальной памяти Linux.

## Вариант A. Трансляция адресов

Размер страницы: 1024 байта. Адресное пространство: 16 КБ (16 страниц).

Формулы:

- page = addr // 1024
- offset = addr % 1024
- physical = frame × 1024 + offset

### Ручные расчёты

**Адрес 1200**

- page = 1200 // 1024 = 1
- offset = 1200 % 1024 = 176
- frame = 2
- physical = 2 × 1024 + 176 = 2224

**Адрес 3100**

- page = 3100 // 1024 = 3
- offset = 3100 % 1024 = 28
- frame = 0
- physical = 0 × 1024 + 28 = 28

**Адрес 5000**

- page = 5000 // 1024 = 4
- offset = 5000 % 1024 = 904
- Страница 4 отсутствует в таблице.
- Результат: страничный отказ.

Программный и ручной расчёты должны совпадать.

### Почему размер страницы выбирают степенью двойки?

Это позволяет быстро вычислять номер страницы с помощью побитового сдвига, а смещение — с помощью битовой маски. Такой способ удобен для аппаратной трансляции адресов.

## Вариант B. Модель TLB

Реализована модель TLB на K записей с алгоритмом замещения LRU.

При попадании HIT перевод берётся из TLB. При MISS система обращается к таблице страниц.

Использованы следующие параметры:

- Доступ к памяти — 100 нс.
- Поиск в TLB — 10 нс.
- При успешном HIT — 110 нс.
- При MISS без страничного отказа — 210 нс.

Формула EAT:

EAT = h × 110 + (1 − h) × 210

### Контрольный пример

При K = 2 на заданном refs.txt:

- HIT: 2
- MISS: 8
- Страничные отказы: 2
- Доля попаданий среди успешных трансляций: 25%
- EAT: 185 нс

Стоимость обработки страничных отказов в EAT не учитывается.

### Двухуровневая таблица

Без TLB для успешного доступа необходимо:

1. Обратиться к таблице первого уровня.
2. Обратиться к таблице второго уровня.
3. Получить данные из памяти.

Итого: 3 обращения к памяти, или 300 нс в принятой модели.

## Вариант C. Реальная виртуальная память Linux

Исследуются:

- /proc/self/maps и /proc/self/pagemap;
- разделяемые отображения через mmap;
- влияние шага обхода массива на время доступа;
- аппаратные счётчики dTLB-load-misses;
- рекомендации ядру с помощью MADV_HUGEPAGE.

Для получения физических номеров кадров (PFN) требуется CAP_SYS_ADMIN. Одного запуска через root в ограниченной среде может быть недостаточно.

В WSL2 доступ к PFN и аппаратным счётчикам TLB может быть ограничен. Невозможность получения этих данных необходимо указывать как ограничение среды, а не заменять предполагаемыми результатами.

## Контрольные вопросы

**1. Почему без TLB страничная организация замедлила бы обращение к памяти вдвое и более?**

Потому что перед чтением данных необходимо сначала получить номер физического кадра из таблицы страниц. При одноуровневой таблице это минимум два последовательных обращения к памяти, а при двухуровневой — три. TLB позволяет часто пропускать обращения к таблицам.

**2. Что хранится в записи таблицы страниц помимо номера кадра?**

В записи могут храниться бит присутствия страницы, права чтения/записи/исполнения, бит изменения (dirty), бит обращения (accessed), а также другие служебные признаки, зависящие от архитектуры.

## Итог

Реализованы программная трансляция адресов, модель TLB с LRU, расчёт EAT и двухуровневая таблица страниц. Подготовлены эксперименты с реальной виртуальной памятью Linux.

TLB уменьшает затраты на трансляцию адресов, а локальность обращений повышает эффективность его использования.
